## Findings considered and rejected

- **Split `planlib.py` into multiple modules**: not worth doing now. It adds
  import and packaging risk in installed skill copies and does not fix the
  main readability problem; the function extraction in plan 002 is the safer
  first step.
- **Replace `dict[str, Any]` row shapes with dataclasses/TypedDicts**: defer.
  It is behavior-neutral but wide churn for low immediate payoff; revisit after
  plan 001 if the row shapes become a recurring source of bugs.
- **Refactor `cmd_*` to explicit parameter objects instead of
  `argparse.Namespace`**: reject. The argparse coupling is conventional and the
  churn is high relative to the benefit.
- **Resolve the plan-cell pending-value drift**: deliberately not planned.
  `planlib.py:784-791` includes `n/a`; `progressive_plan.py:299` does not.
  Unifying them would change `write-plan` behavior for an `n/a` cell, so it
  needs an explicit product/behavior decision, not a silent cleanup.
- **Add a formatter or linter**: not planned in this set. It would add tooling
  and a large unrelated diff; the refactors are surgical and covered by tests.
